---
title: AI 助手
description: 在 NexusPilot 中使用 AI 协助理解数据、探索查询，并安全地处理需要确认的操作。
---

NexusPilot 的 AI 智能助手位于工作台内。它可以帮助你澄清分析目标、理解对象结构、组织查询思路，并在当前模式允许时调用受控的工作台工具。

AI 的回答和建议不是数据库操作已经完成的证明。涉及连接、读取数据或执行操作时，请始终以工作台展示的目标、结果和确认步骤为准。

## 开始前

使用 AI 智能助手前，请确认：

- 本地已完成可用的模型或提供商配置；
- 需要访问数据库时，目标连接能够正常打开；
- 你清楚当前任务的目标、数据范围和环境；
- 不会在对话中粘贴密码、访问令牌、完整连接字符串或不应交给模型处理的敏感数据。

模型与提供商配置由本地 AI Runtime 管理，前端不直接持有 LLM 凭据。

## 选择合适的模式

内置助手根据模式控制可见工具范围。选择模式时，遵循最小权限原则：只使用完成当前任务所需的能力。

| 模式 | 适合的任务 | 数据库工具范围 |
|---|---|---|
| Ask | 梳理思路、解释概念、讨论方案 | 不访问数据库工具 |
| Query | 理解结构、只读探索、组织查询 | 只读数据库工具及必要的连接打开操作 |
| Agent | 需要在受控流程中执行更完整的工作台操作 | 可请求完整的数据库工具范围，实际执行仍受能力与审批限制 |

模式可见的工具范围不等于操作已经获准。每次请求仍会根据当前连接、资源能力、风险级别和确认结果进行独立校验。

## 提出清晰的问题

越清楚地描述目标、范围和约束，助手越容易提供可验证的帮助。推荐包含：

- **目标**：你希望了解、定位或得到什么结果；
- **范围**：应使用哪个连接、数据库对象或时间范围；
- **限制**：只读、不要执行、结果行数上限或必须避免的操作；
- **验收方式**：什么样的结果可以说明问题已解决。

例如：

> 在当前连接中，先只读取用户表的结构。说明可能存放注册时间的字段，并给出一条最多返回 20 行的查询；不要执行写入操作。

在确认目标之前，优先让助手解释计划或生成查询草案，而不是直接要求修改数据。

## 引用连接与快捷命令

在消息开头或空白后输入 `@`，可按名称、驱动或连接 ID 搜索已保存的连接。同名连接会显示驱动和 ID 以便区分。用上下方向键选择候选，按 Enter 或点击候选插入引用；这次 Enter 只选择候选，再次发送才会请求模型。Escape 关闭候选菜单，Tab 关闭菜单并正常移动焦点。邮件地址、代码片段中的 `@` 不会作为引用入口。

选中的引用在输入正文和已发送消息中高亮。已发送消息仅保留正文高亮，不在消息下方重复显示引用来源。输入框与历史编辑中的引用详情展示选择时的名称、驱动和稳定 ID；多次引用同一连接时合并详情并显示次数。修改引用内部的文字会解除该处绑定；详情区的移除按钮会解除该连接的全部绑定，保留正文文字。复制、粘贴和手写 `@名称` 都只是普通文本，不能凭名称建立真实引用。撤销和重做会同时恢复文字与绑定。

连接重命名不会改写旧引用；断开连接也不会使引用失效。连接被删除后，旧消息仍能阅读，但包含该引用的新消息或历史编辑须先移除绑定再发送。连接目录加载失败时可以重试，草稿会保留。每条消息最多 32 处引用、16 个目标和 32 KiB 引用信息。

在一行开头（可有空白）输入 `/` 可选择快捷命令：

| 命令 | 效果 |
|---|---|
| `/help` | 在本地显示当前可用命令与引用说明。 |
| `/explain` | 保留高亮短命令，继续输入或粘贴 SQL 后发送；AI Runtime 为模型展开解释提示词，输入和已发送消息不显示长提示词。 |
| `/compact` | 选择后单独发送，主动压缩当前会话的上下文；结果以压缩活动展示，原始历史仍保留。 |

每条消息最多绑定一个消息提示命令，可以与多个连接引用共存。命令选择后不会立即发送；输入和已发送消息中的 `/explain` 均保持高亮，历史编辑也会恢复绑定。修改命令内部文字会解除绑定，复制粘贴或直接输入同名文字不会自动建立命令绑定。命令提示词按发送时的版本保存，后续更新不会改写历史含义。

`/compact` 需要单独提交，不能混入正文、引用或附件。空会话、模型不可用、正在回复或等待审批时不可执行；压缩期间可以继续写草稿，但需等待完成或取消后才能发送。压缩使用当前选定模型生成摘要，会消耗模型 tokens；没有安全可压缩的历史时会提示无需压缩。失败可以重试，取消不会清空草稿或原始消息。刷新或重启后仍可读取操作结果，中断的操作不会自动重新执行。切换到足够大的上下文窗口时，Runtime 仍可能恢复使用完整原文。

选择引用或命令不会连接数据库、读取数据、执行 SQL、自动发送消息或切换模式。发送时，引用的名称、驱动和稳定连接 ID 会作为用户提供的上下文交给当前模型；这些描述不代表连接实时状态或操作授权。当前仅提供连接引用，正文高亮暂不支持点击跳转。

历史消息编辑使用同一套输入能力。请求被拒绝或连接 Runtime 失败时，界面提供“恢复未发送草稿”，恢复正文、附件与引用；有新草稿时需先处理新草稿，以免被覆盖。恢复草稿只保留在当前应用会话内，已成功提交的消息由 Runtime 持久保存。

## 发送附件

你可以在消息编辑区选择、拖拽或粘贴图片、音频、PDF 和其他文件。附件会先上传到本机 AI Runtime；进度完成并取得最终附件记录后，才能与文本一起发送，也可以单独发送纯附件消息。上传失败时，原文本和附件会保留，便于重试或移除。

历史消息先显示附件元数据；图片在进入可见区域时按需读取，普通文件只在点击下载时读取。若本地附件内容损坏或已经不可用，消息仍保留文件名和类型并显示明确提示。

图片支持预览，其他文件以文件卡片显示；点击文件卡片后可选择保存位置，保存成功或失败时界面会给出明确反馈。历史附件由本机 Runtime 保存，因此原文件移动、删除或应用重启后仍可从对话中读取。单个附件默认不超过 25 MiB；一条消息最多 10 个附件且总量不超过 50 MiB。

首次添加附件时，界面会提醒：附件内容将发送给当前选择的外部 AI Provider，并受其数据处理政策约束。NexusPilot 不根据模型目录中的视觉或附件标签预先阻止发送；若当前模型不支持该类型，Run 会失败并在对应 Assistant 消息中显示 Provider 或 AI SDK 返回的错误正文，不会静默删除附件或改成纯文本重试。请不要上传密码、访问令牌、私钥或不应交给外部模型处理的敏感文件。

## 理解上下文与结果

当模式和连接能力允许时，助手会通过受控工具读取连接、对象元数据、表格数据或 Key/Value 信息。它不会因为你提到了某个数据库名称，就自动拥有该数据库的所有权限。

后续回合会从本地 Runtime 保存的会话事实重建上下文，包括先前的 Assistant 文本、reasoning、工具名称、工具输入以及成功、失败或中断结果。历史工具调用只作为已经发生的事实交给模型，不会因为进入下一回合而重新执行，也不会重新打开旧审批。切换 Provider 或模型时，Runtime 会移除旧模型专属 metadata，并把可读的 reasoning 降级为普通 Assistant 文本；普通文本和工具调用/结果仍保留。

长对话接近当前模型的上下文窗口时，Runtime 会在首次模型请求和一次工具 step 完整结束后的下一请求前重新规划，并可在同一条 Assistant Run 中自动压缩、立即继续。压缩发生处会作为消息流中的独立分隔元素显示，而不是常驻在某条 Assistant 消息底部：准备时显示“正在压缩上下文…”，成功或 overflow 恢复成功时显示“上下文已压缩”，失败时显示“上下文压缩失败”，取消或并发失效时显示“上下文压缩已中止”。这些元素只表达生命周期，不显示摘要正文、模型 reasoning、安全状态或诊断详情，也不会被当作用户消息编辑。原始消息、工具记录、审批和附件引用仍保留在本机审计历史中。编辑一条已完成的用户消息会创建新的当前分支：之后的默认对话显示和模型上下文会跟随新分支，旧分支事实不会因此被删除或让已经发生的外部操作失效。

模型生成、上下文压缩、工具执行或审批等待可能持续较长时间；AI Runtime 不会仅因为核心 HTTP、SSE 或 Backend Bridge 在一段时间内没有业务输出就按固定的短时限中断它们。用户主动停止、Provider/工具自身的业务超时、Runtime 退出与连接活性检测仍会正常终止对应工作，并保留实际终止来源。

输入区的主上下文百分比表示 Runtime 对“下一轮调用将占用多少目标模型窗口”的估算；一轮完成时会包含刚生成的最新 Assistant 内容。它不把输出预留、Provider 最近实测输入或整次 Run 的累计 token/计费总数混进主值，这些数据只在辅助说明中分别展示。同一模型、当前分支和策略下，追加对话时主值不会因为请求阶段或数据来源切换而反向跳动；成功压缩、编辑/切换分支、切换模型或策略变化时可以重新计算并下降。若 Runtime 没有可信的窗口事实，界面会显示未知。Runtime 不自动改用其他模型；只有在请求尚未输出、调用工具、请求审批或产生副作用时遇到明确的上下文超限，才会对同一 Provider/model 安全重试一次。达到自动压缩阈值后，如果摘要生成失败，本轮会直接失败而不会静默发送未经压缩的完整历史；错误仍显示本次 Provider/AI SDK 的原始正文，Runtime 自身发现空摘要等校验问题时则显示稳定的 Runtime 错误正文。

请在每次操作前检查：

1. 目标连接和对象是否正确；
2. 返回的数据范围是否符合预期；
3. 助手提出的 SQL、筛选条件或 Key 是否准确；
4. 当前环境是否为生产环境，以及是否需要额外审核。

## 审批与高风险操作

数据库工具的可见性、数据库实际能力和操作授权是三层独立边界。即使助手能够提出操作，它也不能绕过工作台的风险分析与确认。

- 原始 SQL 会先经过单语句边界与风险分析；无法可靠分类的 SQL 会按高风险处理。
- Redis Key 的创建、替换、重命名、TTL 修改和删除使用受控的单 Key 操作，不接受任意 Redis 命令或批量删除请求。
- 高风险 SQL 和 Redis 写入会要求确认；精确删除与设置过期 TTL 等操作会使用更强的确认要求。

看到确认提示时，请核对目标、语句或 Key、影响范围和环境。内容不清楚、目标不正确或范围超出预期时，拒绝确认并要求助手先解释或缩小操作。

## 保护数据与凭据

AI Runtime 在本地管理模型与提供商配置，但你仍应按所选模型提供商的数据政策处理业务数据。建议：

- 不在提示词中粘贴不必要的大段敏感数据；
- 先使用结构、字段名、聚合结果或脱敏样本验证思路；
- 生产环境优先采用只读范围，并遵循团队既有的审核和备份流程；
- 将数据库实际结果视为事实来源，不以模型文本替代核验。

## AI 不可用时

AI Runtime 不可用不会替代或阻塞数据库工作台的基础能力。你仍可以管理连接、浏览对象和按当前连接能力执行工作台操作。

若助手无法响应，请检查模型 / 提供商配置、网络连接和应用显示的错误信息；反馈时不要包含 API Key 或敏感对话内容。更多排查步骤见[故障排查](/help/troubleshooting/)。

## 查看模型执行错误

AI SDK 或 Provider 在模型执行期间返回错误时，错误卡会出现在对应 Assistant 消息的位置。错误正文保留 Provider/AI SDK 返回的原始换行和空白；长内容可在卡片内滚动，并可以直接复制。刷新页面或重启本地 Runtime 后，已持久化的错误仍会从会话历史恢复。

NexusPilot 不翻译、解释或用通用产品文案替换该正文。唯一例外是：如果错误正文精确包含 Runtime 当前持有的完整 API Key 等 secret，只替换该精确 secret；正文中的普通 URL、模型名、请求 ID、状态码和 Provider 说明不会被模式化删改。数据库工具自身的错误仍显示在对应工具卡中，AI Runtime 不可用或传输中断仍使用独立的基础设施提示。
