---
title: AI 助手
description: 在 NexusPilot 中使用 AI 协助理解数据、探索查询，并安全地处理需要确认的操作。
---

NexusPilot 的 AI 智能助手位于工作台内。它可以帮助你澄清分析目标、理解对象结构、组织查询思路，并在当前模式允许时调用受控的工作台工具。

AI 的回答和建议不是数据库操作已经完成的证明。涉及连接、读取数据或执行操作时，请始终以工作台展示的目标、结果和确认步骤为准。

## 开始前

使用 AI 智能助手前，请确认：

- 本地已完成可用的模型或提供商配置；
- 需要访问数据库时，目标连接能够正常打开；
- 你清楚当前任务的目标、数据范围和环境；
- 不会在对话中粘贴密码、访问令牌、完整连接字符串或不应交给模型处理的敏感数据。

模型与提供商配置由本地 AI Runtime 管理，前端不直接持有 LLM 凭据。

## 选择合适的模式

内置助手根据模式控制可见工具范围。选择模式时，遵循最小权限原则：只使用完成当前任务所需的能力。

| 模式 | 适合的任务 | 数据库工具范围 |
|---|---|---|
| Ask | 梳理思路、解释概念、讨论方案 | 不访问数据库工具 |
| Query | 理解结构、只读探索、组织查询 | 只读数据库工具及必要的连接打开操作 |
| Agent | 需要在受控流程中执行更完整的工作台操作 | 可请求完整的数据库工具范围，实际执行仍受能力与审批限制 |

模式可见的工具范围不等于操作已经获准。每次请求仍会根据当前连接、资源能力、风险级别和确认结果进行独立校验。

## 提出清晰的问题

越清楚地描述目标、范围和约束，助手越容易提供可验证的帮助。推荐包含：

- **目标**：你希望了解、定位或得到什么结果；
- **范围**：应使用哪个连接、数据库对象或时间范围；
- **限制**：只读、不要执行、结果行数上限或必须避免的操作；
- **验收方式**：什么样的结果可以说明问题已解决。

例如：

> 在当前连接中，先只读取用户表的结构。说明可能存放注册时间的字段，并给出一条最多返回 20 行的查询；不要执行写入操作。

在确认目标之前，优先让助手解释计划或生成查询草案，而不是直接要求修改数据。

## 发送附件

你可以在消息编辑区选择、拖拽或粘贴图片、音频、PDF 和其他文件。附件会先上传到本机 AI Runtime；进度完成并取得最终附件记录后，才能与文本一起发送，也可以单独发送纯附件消息。上传失败时，原文本和附件会保留，便于重试或移除。

历史消息先显示附件元数据；图片在进入可见区域时按需读取，普通文件只在点击下载时读取。若本地附件内容损坏或已经不可用，消息仍保留文件名和类型并显示明确提示。

图片支持预览，其他文件以文件卡片显示；点击文件卡片后可选择保存位置，保存成功或失败时界面会给出明确反馈。历史附件由本机 Runtime 保存，因此原文件移动、删除或应用重启后仍可从对话中读取。单个附件默认不超过 25 MiB；一条消息最多 10 个附件且总量不超过 50 MiB。

首次添加附件时，界面会提醒：附件内容将发送给当前选择的外部 AI Provider，并受其数据处理政策约束。NexusPilot 不根据模型目录中的视觉或附件标签预先阻止发送；若当前模型不支持该类型，Run 会失败并显示安全错误，不会静默删除附件或改成纯文本重试。请不要上传密码、访问令牌、私钥或不应交给外部模型处理的敏感文件。

## 理解上下文与结果

当模式和连接能力允许时，助手会通过受控工具读取连接、对象元数据、表格数据或 Key/Value 信息。它不会因为你提到了某个数据库名称，就自动拥有该数据库的所有权限。

请在每次操作前检查：

1. 目标连接和对象是否正确；
2. 返回的数据范围是否符合预期；
3. 助手提出的 SQL、筛选条件或 Key 是否准确；
4. 当前环境是否为生产环境，以及是否需要额外审核。

## 审批与高风险操作

数据库工具的可见性、数据库实际能力和操作授权是三层独立边界。即使助手能够提出操作，它也不能绕过工作台的风险分析与确认。

- 原始 SQL 会先经过单语句边界与风险分析；无法可靠分类的 SQL 会按高风险处理。
- Redis Key 的创建、替换、重命名、TTL 修改和删除使用受控的单 Key 操作，不接受任意 Redis 命令或批量删除请求。
- 高风险 SQL 和 Redis 写入会要求确认；精确删除与设置过期 TTL 等操作会使用更强的确认要求。

看到确认提示时，请核对目标、语句或 Key、影响范围和环境。内容不清楚、目标不正确或范围超出预期时，拒绝确认并要求助手先解释或缩小操作。

## 保护数据与凭据

AI Runtime 在本地管理模型与提供商配置，但你仍应按所选模型提供商的数据政策处理业务数据。建议：

- 不在提示词中粘贴不必要的大段敏感数据；
- 先使用结构、字段名、聚合结果或脱敏样本验证思路；
- 生产环境优先采用只读范围，并遵循团队既有的审核和备份流程；
- 将数据库实际结果视为事实来源，不以模型文本替代核验。

## AI 不可用时

AI Runtime 不可用不会替代或阻塞数据库工作台的基础能力。你仍可以管理连接、浏览对象和按当前连接能力执行工作台操作。

若助手无法响应，请检查模型 / 提供商配置、网络连接和应用显示的错误信息；反馈时不要包含 API Key 或敏感对话内容。更多排查步骤见[故障排查](/help/troubleshooting/)。
