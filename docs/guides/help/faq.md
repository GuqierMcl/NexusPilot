---
title: 常见问题
description: 关于安装、数据库支持、连接状态和数据安全的常见问题。
---

## 当前支持哪些数据库？

请查看[官网数据库支持矩阵](https://nexuspilot.dev/#databases)。它是当前可用数据源与规划状态的唯一公开来源，文档不会维护重复列表。

## 为什么某个连接已打开，但没有显示全部对象？

对象树采用按需加载。先展开连接或父节点，再等待其子对象加载。不同数据源返回的对象层级不同，而且数据库权限也会影响可见范围。

## 为什么数据视图是只读的？

是否可编辑取决于资源类型、数据库能力、当前权限和安全边界。某些对象没有可靠的行定位方式，或其原生语义无法安全映射为通用编辑操作，因此会保持只读。

## 能否直接在生产环境执行操作？

可以连接生产环境并在拥有权限时执行相应操作，但应始终遵守团队的变更、审核和备份流程。执行前确认连接名称、目标上下文、查询条件与影响范围；不确定时优先使用只读查询或非生产环境验证。

## AI 是否会自动修改数据库？

涉及数据库操作时，应以工作台的目标信息、风险提示和确认步骤为准。不要把 AI 的建议视为已经执行，也不要跳过应用展示的审批或确认。

## 模型凭据由谁保存？

NexusPilot 的本地 AI Runtime 负责管理模型和提供商配置，前端不直接持有 LLM 凭据。具体可用模型和配置方式取决于当前应用版本与本地设置。

## 我可以导入其他数据库工具的连接吗？

请以当前版本的连接创建界面和发布说明为准。尚未提供的导入方式不应通过手工修改本地应用数据来替代。

## 更新会删除我的连接吗？

正常更新应保留合法的本地应用数据。更新前仍建议保存重要工作内容，并在升级后打开连接列表确认关键配置可用。

## 如何手动刷新 Cloud 连接状态？

登录后，点击底部状态栏的 Cloud 状态项即可刷新，行为与打开账号卡片时的刷新一致。刷新过程中会显示连接进度，重复点击不会重复发起请求；刷新结果会同步更新账号卡片和状态栏。需要同步连接数据时，仍使用 Cloud 设置中的“立即同步”。

## 新设备已授权，为什么 Cloud 同步仍提示“返回了无法识别的响应”？

这条提示也可能由下载后的数据校验或本地保存失败触发，不能仅凭文案判断为登录失败或服务端响应格式错误。新设备首次同步会恢复连接及其文件夹层级；客户端会在同一批数据中先处理父文件夹，再处理子文件夹和连接。

旧版下载的文件夹还可能存在时间字段存储格式不一致的问题，导致后续同步在读取本地文件夹时失败。包含兼容修复的客户端可以直接读取这些已有记录，无需清空云端数据库、删除本地连接或重新授权设备。

如果处理冲突并选择“保留本地”后出现 `pull.validate` / `DecryptionFailed`，旧版可能上传了与修订号不匹配的密文。先在当时处理冲突的设备上安装包含修复的版本并同步；客户端在本机历史记录完整、仍有写入权限且能验证原始候选时，会定向修复该记录，再重新拉取。随后同步其他设备。保留该设备的本地数据和授权，不需要清空 Cloud。无法匹配历史记录时仍会停止同步，应联系支持继续定位。

“保留二者”会让原连接采用 Cloud 版本，并为本地候选创建独立连接；“保留 Cloud”会更新本地同步基准。若曾用旧版“保留二者”，请核对副本的实际连接参数：旧实现可能复制了 Cloud 参数，升级不会自动猜测并覆盖已经生成的副本。

确认两台设备使用相同的最新版本，并在新设备重试“立即同步”。如果仍然失败，向支持提供应用版本、失败时间，以及主进程日志中以 `Cloud sync failed` 或 `Cloud response rejected` 开头的诊断行。包含这些诊断的版本会标明失败阶段；旧版本可能只有通用提示。Windows 正式版主进程日志位于 `%LOCALAPPDATA%\NexusPilot\logs\`，开发模式日志显示在启动应用的终端中。
