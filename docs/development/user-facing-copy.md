# 用户可见文案指南

> 最后更新：2026-07-18

本指南约束 NexusPilot 界面、Toast、Dialog、表单校验和 IPC 用户消息中的文案。研发路线图、测试名称、fixture、仅开发者可见的诊断日志可以保留内部阶段标识，但这些标识不能进入用户交互。

## 核心规则

当功能受限、操作失败或能力尚未开放时，用户提示必须回答三个问题：

1. **发生了什么**：明确指出当前不能完成的操作或当前状态。
2. **为什么**：使用产品或数据安全语义说明限制原因；原因未知时如实说明不能确认结果。
3. **下一步怎么做**：提供当前可执行的替代路径、检查项或恢复方式。没有安全替代方案时，应明确告知用户保持数据不变并建议稍后重试或联系管理员。

用户不需要理解研发过程。面向用户的文案不得包含以下内部术语：

- `Phase 3`、`Phase 5E` 等阶段编号；
- backlog、milestone、capability gate 等研发规划或发布门禁名称；
- fixture、runner、checkpoint 等测试基础设施术语；
- 只能通过阅读路线图才能理解的缩写或任务编号。

描述订阅或套餐时，不得把套餐价值写死为当前唯一已经实现的能力。NexusPilot Cloud 后续可能提供连接同步、AI 同步、设置同步等不同权益，因此账户卡片、套餐总览和升级入口优先使用“Cloud 权益”或“账户权益”，再列出具体能力。功能级状态可以准确写“当前账户未获得连接同步权益”，但不应写成“Plus 就是连接同步”或暗示订阅只包含连接同步。

## 推荐写法

| 场景 | 不应使用 | 推荐使用 |
| --- | --- | --- |
| ClickHouse 旧式主键接口不可用 | `ClickHouse table mutation is not available in Phase 3` | `该操作使用的主键定位方式不适用于 ClickHouse；请刷新 DataTable 后通过“保存更改”提交，或在 SQL 编辑器中执行写入操作` |
| 无安全行定位方式 | `Phase 4 不支持无主键表` | `该表没有显式主键，无法安全定位要修改或删除的行；当前仅支持浏览数据` |
| 设计器限制 | `Phase 5C 只支持 SAMPLE BY` | `为避免改变表的数据组织方式，其他键保持只读；当前只能修改 SAMPLE BY。如需调整，请确认迁移影响后使用 SQL 编辑器` |
| 结果无法确认 | `commit failed` | `请求已发送，但当前无法确认服务端是否完成写入。请刷新数据并核对目标行，不要直接重复提交` |
| 账户没有当前同步权益 | `Plus 才能同步连接` | `当前账户未获得连接同步权益；你仍可正常使用本地连接，并可在账户页面查看可用的 Cloud 权益` |

## 错误与诊断边界

- `IpcError.message` 会展示给用户，必须遵守本指南。
- `IpcError.details` 只用于开发诊断，可以使用精确技术术语，但不得包含密码、连接串或其他秘密。
- Toast 或 Dialog 不应直接展示仅面向开发者的异常字符串；需要将其映射为可操作的用户消息，并把技术细节保留在诊断信息中。
- 错误码用于程序分支，不替代用户解释。
- 如果操作可能已经提交但结果未知，必须明确提示用户先刷新或核对事实，不能建议无条件重试。

## 评审与测试

- 新增或修改用户交互时，评审必须检查“三要素”：发生了什么、为什么、下一步怎么做。
- `scripts/user-facing-copy.test.ts` 会扫描生产前端源码，阻止阶段编号重新进入界面文案。
- Rust 驱动对关键限制消息使用聚焦单元断言，确保用户消息不包含阶段编号，并与 `details` 的诊断职责分离。
- 路线图、单元测试名称和真实库 marker 可以继续使用阶段编号；回归检查不应把这些内部证据误判为用户文案。
